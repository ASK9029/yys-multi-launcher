# 阴阳师 PC 端多开启动器 (YysMulti)

一个只做「启动 + 窗口管理」的小工具，用来在 Windows 上稳定地多开《阴阳师》PC 客户端。

- 默认全部直连 `bin\onmyoji.exe`，**普通权限**，可以被正常移动和排版
- 自动错峰启动、自动排版、一键全关
- 屏幕放不下时，可把多出的实例放进 **Windows 11 虚拟桌面**
- 全程无控制台窗口，支持 Per-Monitor DPI

> 本项目**不修改游戏文件、不读写游戏内存、不模拟操作、不含任何游戏资源**。
> 只做进程启动与窗口位置管理，与网易/阴阳师官方无关。

---

## 1. 两个关键机制

### 1.1 启动器 `Launch.exe` 是提权程序

`Launch.exe` 的清单是 `requireAdministrator`，它拉起的客户端会继承管理员完整性级别。
而普通权限的多开器对它调用 `SetWindowPos` 会直接失败：

```
SetWindowPos(...) -> False, GetLastError() = 5 (ERROR_ACCESS_DENIED)
```

结果就是**那个窗口永远停在默认位置和尺寸，把其它窗口挤乱**——这正是「多开几个后窗口打乱」的主要原因。

所以本工具默认**不走启动器**，直接启动 `bin\onmyoji.exe`（普通权限）。
如果你需要启动器做版本/补丁校验，可以加 `/launcher`，但要接受「第一个实例无法被排版」。

### 1.2 客户端会自己改窗口尺寸

实测同一个窗口，请求 `1348x713` 会被改成 `1188x713`，请求 `1268x713` 可能变成 `1268x758`，
不同实例的修正结果还不一致。所以排版不能硬套 16:9 网格，本工具的做法是：

1. 先尽量把窗口设成目标格子大小；
2. 读回每个窗口的**真实尺寸**；
3. 按「每行最大高度」逐个打包，保证互不重叠；
4. 遇到管理员实例（改不动）直接跳过并写日志。

## 2. 功能

| 功能 | 说明 |
| --- | --- |
| 多开 | 默认 2 个，可 1~12 个 |
| 错峰 | 实例之间等待 12 秒，避免同时读写配置/缓存 |
| 自适应排版 | 先设格子再按实际尺寸打包，不重叠、不跑到屏幕外 |
| 容量检测 | 按最小可用格子算出单屏容量（2560x1600 约 6 个） |
| 虚拟桌面 | 超出容量时弹窗询问，自动新建桌面并把多余实例开在那边 |
| 一键全关 | `YysMulti.exe /close` |
| 重新排版 | `YysMulti.exe /arrange`（只处理当前桌面） |

## 3. 快速开始

### 3.1 编译

只需要 .NET Framework 4.x 自带的 `csc.exe`，不需要 Visual Studio：

```powershell
.\build.ps1
```

产物：`dist\YysMulti.exe`（`winexe`，无控制台）。

### 3.2 安装

把 `YysMulti.exe` 放到游戏根目录，也就是与 `Launch.exe` 同级：

```
<游戏根目录>\
├── Launch.exe
├── YysMulti.exe        ← 放这里
├── bin\
│   └── onmyoji.exe
```

程序通过自身所在目录定位游戏，不需要配置路径，也不写注册表。

### 3.3 参数

| 参数 | 作用 |
| --- | --- |
| 无 | 开 2 个 |
| `3` | 开 3 个 |
| `/close` | 关闭所有客户端 |
| `/arrange` | 只重排当前桌面的窗口 |
| `/keep` | 只启动，不排版 |
| `/plan 6` | 只计算版面写日志，不启动游戏 |
| `/launcher` | 第一个实例改走 `Launch.exe`（管理员，无法排版） |
| `/capacity N` | 调试用：覆盖单屏容量 |
| `/forcevd` | 调试用：强制使用虚拟桌面 |

## 4. 虚拟桌面功能

屏幕放不下时（实例数 > 容量），程序会弹窗询问：

> 当前屏幕最多能舒适放下 6 个实例，多出的可以放到新的虚拟桌面……是否使用虚拟桌面？

选择「是」后：

1. `Win+Ctrl+D` 新建桌面并切过去；
2. 在新桌面启动实例；
3. 等窗口出现并排版；
4. `Win+Ctrl+←` 切回原桌面。

**实现约束**（都是实测出来的）：

- 没有公开 API 能创建/切换桌面，只能模拟热键；
- `IVirtualDesktopManager.MoveWindowToDesktop` 在 Win11 25H2 上返回 `E_ACCESSDENIED`，
  所以不能事后搬运窗口，必须「先切过去、开完再切回来」；
- `EnumWindows` 看不到其它桌面的窗口，程序靠记住 hwnd 继续操作；
- 如果前台是管理员窗口，热键会被 UIPI 拦掉，程序会检测到「桌面没切成」并退回到当前桌面。

## 5. 高 DPI 兼容性

`bin\onmyoji.exe` 自身没有 DPI 感知声明，会继承父进程的 DPI 感知：

| 启动方式 | 父进程 | 结果 |
| --- | --- | --- |
| `Launch.exe`（带 `~ HIGHDPIAWARE`） | 系统级 DPI 感知 | Per-Monitor / 144 DPI，清晰 |
| 未声明 DPI 的程序直连 | DPI UNAWARE | 被系统位图拉伸，糊 |

解决办法（任选其一）：

1. 给 `bin\onmyoji.exe` 打兼容性标记（等价于右键 → 属性 → 兼容性 → 更改高 DPI 设置 →
   勾选「替代高 DPI 缩放行为」，选「应用程序」）：

   ```
   HKCU\Software\Microsoft\Windows NT\CurrentVersion\AppCompatFlags\Layers
   值名：<游戏根目录>\bin\onmyoji.exe
   值：  ~ HIGHDPIAWARE
   ```

2. 本项目自身已声明 `PerMonitorV2`（见 `src/app.manifest`）。

## 6. 已知限制

- **管理员实例无法排版**：如果某个实例是通过 `/launcher` 或手动以管理员身份启动的，
  普通权限下移动会被拒绝（日志会写「UIPI 拒绝」）。建议统一用本工具默认方式启动。
- 客户端进入游戏后可能锁定自己的窗口尺寸，此时排版只能改位置、改不了大小。
- 虚拟桌面热键在前台为管理员窗口时会失效（会安全退回当前桌面）。
- 只支持单显示器主屏排版。

## 7. 注意事项

1. **不要用于自动化**。本项目不含自动战斗、脚本点击、内存读写等功能。
2. 16 GB 内存建议 2~3 个实例，6 个以上注意内存和显存。
3. 双开请使用**不同账号**。
4. `/close` 会结束所有 `onmyoji` / `Launch` 进程，使用前确认没有要保留的实例。
