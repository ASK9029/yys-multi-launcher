# 阴阳师 PC 端多开启动器 (YysMulti)

一个只做「启动 + 窗口管理」的小工具，用来在 Windows 上稳定地多开《阴阳师》PC 客户端。

- **第 1 个实例走官方 `Launch.exe`**，保证版本/补丁校验正常
- **后续实例直连 `bin\onmyoji.exe`**，绕开启动器的单实例保护
- 错峰启动、自动按 16:9 并排、一键全关
- 全程无控制台窗口，支持 Per-Monitor DPI

> 本项目**不修改游戏文件、不读写游戏内存、不模拟操作、不含任何游戏资源**。
> 只做进程启动与窗口位置管理，与网易/阴阳师官方无关。

---

## 1. 它解决什么问题

《阴阳师》PC 客户端的启动器 `Launch.exe` 内部有单实例保护：

```
OnmyojiLaunch                  ← 启动器互斥体
KillClient(onmyoji.exe)        ← 启动前会先杀掉已在运行的客户端
.\bin\onmyoji.exe              ← 校验通过后才真正拉起客户端
```

所以「连点两次启动器」并不能多开，第二次往往把第一个顶掉。而直接运行 `bin\onmyoji.exe` 是可以并存的——本项目就是把这两种方式组合起来，并补上排版、错峰、DPI 这些细节。

## 2. 功能

| 功能 | 说明 |
| --- | --- |
| 多开 | 默认 2 个，可 1~6 个 |
| 启动器感知 | 第一个实例走 `Launch.exe`，其余走 `bin\onmyoji.exe` |
| 错峰 | 两个实例之间等待 10~12 秒，避免同时读写 `Documents` 下的配置/缓存 |
| 自动并排 | 按 16:9 网格排列，2 个窗口左右各半屏 |
| 一键全关 | `YysMulti.exe /close` |
| 重新排版 | `YysMulti.exe /arrange` |
| 无黑框 | 编译为 `winexe`，不创建任何控制台窗口 |
| 高 DPI | 程序自带 `PerMonitorV2` 清单，坐标按物理像素计算 |

## 3. 快速开始

### 3.1 编译

只需要 .NET Framework 4.x 自带的 `csc.exe`，不需要 Visual Studio：

```powershell
.\build.ps1
```

产物：`dist\YysMulti.exe`（`winexe`，无控制台）。

### 3.2 安装

把 `YysMulti.exe` 放到游戏根目录，也就是与 `Launch.exe` 同级：

```
<游戏根目录>\
├── Launch.exe
├── YysMulti.exe        ← 放这里
└── bin\
    └── onmyoji.exe
```

程序通过自身所在目录定位游戏，**不需要配置路径**，也不写注册表。

### 3.3 使用

| 操作 | 效果 |
| --- | --- |
| 双击 `YysMulti.exe` | 开 2 个并自动并排 |
| `YysMulti.exe 3` | 开 3 个 |
| `YysMulti.exe /close` | 关闭所有客户端 |
| `YysMulti.exe /arrange` | 只对已开窗口重新排版 |

建议给 `/close` 建一个快捷方式放桌面，方便一键收工。

日志写在 `YysMulti-log.txt`（与 exe 同目录），方便排查“为什么没排上”。

## 4. 高 DPI 兼容性（重要）

这是多开工具最容易踩的坑，也是本项目专门处理过的地方。

### 4.1 现象

第二个实例画面发糊、游戏内分辨率明显偏低，第一个却正常。

### 4.2 原因

`bin\onmyoji.exe` 自身没有 DPI 感知声明，会**继承父进程的 DPI 感知级别**：

| 启动方式 | 父进程 DPI 感知 | 子进程结果 |
| --- | --- | --- |
| `Launch.exe`（带 `~ HIGHDPIAWARE` 兼容性标记） | 系统级 DPI 感知 | Per-Monitor / 144 DPI，清晰 |
| 普通未声明 DPI 的程序直连 | DPI UNAWARE | 被系统位图拉伸，糊 |

也就是说：**谁拉起客户端，决定了客户端清不清晰**。

### 4.3 解决

两种做法，任选其一（同时做也不冲突）：

1. **给 `bin\onmyoji.exe` 打兼容性标记**（推荐，对所有启动方式生效）

   等价于右键 `onmyoji.exe` → 属性 → 兼容性 → 更改高 DPI 设置 →
   勾选“替代高 DPI 缩放行为”，缩放执行选“应用程序”。

   对应注册表：

   ```
   HKCU\Software\Microsoft\Windows NT\CurrentVersion\AppCompatFlags\Layers
   值名：<游戏根目录>\bin\onmyoji.exe
   值：  ~ HIGHDPIAWARE
   ```

2. **让多开器自身 DPI 感知**：仓库内 `src/app.manifest` 已声明 `PerMonitorV2`，
   用 `build.ps1` 编译会自动嵌入。

撤销：删除上述注册表值，或在兼容性界面取消勾选。

## 5. 实现要点

```
Main()
 ├─ /close     → 结束 onmyoji / onmyoji_future / Launch 进程
 ├─ /arrange   → 枚举现有窗口并排版
 └─ 默认
     ├─ 统计已有 onmyoji 实例数
     ├─ 若一个都没开 且存在 Launch.exe → 启动 Launch.exe，轮询等新的 onmyoji.exe 出现
     ├─ 其余实例 → 直接启动 bin\onmyoji.exe，间隔 10~12 秒
     ├─ 轮询各 PID 的顶层窗口（标题含“阴阳师”优先，否则取面积最大者）
     └─ SetWindowPos 按 16:9 网格摆放
```

几个实现细节：

- **窗口选择**：同一进程可能有启动画面、登录框、主窗口多个顶层窗口，
  这里优先匹配标题含“阴阳师”的窗口，否则退化为“面积最大的可见窗口”。
- **排版失败要能看出来**：`SetWindowPos` 之后会再 `GetWindowRect` 读回真实矩形写进日志，
  日志里的“目标 / 实际”不一致，说明被客户端拒绝了。
- **不抢焦点**：排版使用 `SWP_NOACTIVATE`，不会把游戏窗口顶到最前打断你操作。

## 6. 已知限制

- 客户端在**登录界面阶段**允许改窗口尺寸，**进入游戏后可能锁定自己的窗口大小**，
  此时排版只能移动位置、改不了大小。这是游戏自身行为，不是工具缺陷。
- 窗口识别依赖进程名 `onmyoji.exe` / `onmyoji_future.exe` 与标题关键字，
  客户端大版本更新若改名，需要同步修改 `src/YysMulti.cs`。
- 只支持单显示器主屏排版；多屏支持可以自行扩展 `Screen.PrimaryScreen`。

## 7. 注意事项

1. **不要用于自动化**。本项目不含自动战斗、脚本点击、内存读写等功能，
   也不建议配合第三方脚本使用——那是另一回事，且有封号风险。
2. 多开本身会占用较多内存，16 GB 机器建议 2~3 个实例。
3. 双开请使用**不同账号**，同一账号多开会互相顶号。
4. 工具会结束同名进程（`/close` 时），使用前确认没有其他需要保留的实例。
5. 游戏更新后如果启动器逻辑变化（例如不再 `KillClient`），本工具的“第一个走启动器”策略可能需要调整。
